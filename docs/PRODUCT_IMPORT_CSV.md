# Product Import CSV

**Endpoint:** `POST /api/v1/admin/products/import`  
**Authentication:** Sanctum admin access  
**Last verified:** September 26, 2026

Upload a CSV as `multipart/form-data` with:

- `file`: CSV/plain-text file, maximum 5 MB.
- `dry_run`: required boolean. String values such as `true`, `false`, `1`, and `0` are normalized before validation.

Always run with `dry_run=true` first. A preview performs the same row validation and create/update classification without writing data.

## File-level rules

- The first row is the header. A UTF-8 BOM on the first header is accepted.
- Headers must be unique and non-empty.
- `type`, `sku`, and `name` headers are mandatory.
- At least one data row is required; the maximum is 5,000 data rows.
- Extra headers are accepted but ignored unless listed below.
- Empty cells are omitted from the normalized row.
- The literal `NULL` is converted to a real null value, which can clear a nullable imported field on update.
- `options` and `attributes` are JSON strings in the CSV and must decode to JSON objects/arrays.
- SKUs must be unique within the file, case-insensitively.

## Product rows

Set `type` to `product`.

| Column | Required | Rules and behavior |
|---|---:|---|
| `type` | Yes | Must be `product` |
| `sku` | Yes | String, max 255; creates or updates by SKU; cannot collide with a variant or soft-deleted product |
| `name` | Yes | String, max 255 |
| `slug` | No | String, max 255; uniqueness is generated by the backend |
| `description` | No | String, max 10,000 |
| `price` | Yes | Number, minimum 0 |
| `discount_price` | No | Number, minimum 0 and strictly less than `price` |
| `stock_qty` | No | Integer, minimum 0; if `in_stock` is omitted, it is derived from this value |
| `status` | No | `draft`, `published`, or `archived`; new products default to `draft`, existing products retain status when omitted |
| `category_slug` | For published rows | Must identify an existing category |
| `in_stock` | No | Boolean (`true/false`, `1/0`, and standard boolean spellings accepted by PHP normalization) |
| `is_featured` | No | Boolean |
| `meta_title` | No | String, max 255 |
| `meta_description` | No | String, max 1,000 |
| `options` | No | Valid JSON array/object |
| `weight_oz` | For published rows | Number greater than 0, maximum 2,400 |
| `length_in` | For published rows | Number greater than 0, maximum 200 |
| `width_in` | For published rows | Number greater than 0, maximum 200 |
| `height_in` | For published rows | Number greater than 0, maximum 200 |

Important update behavior: an omitted `category_slug` clears the category on a draft or archived product. Include the current category slug when it must be preserved. Published products cannot omit it.

## Variant rows

Set `type` to `variant`. Products are committed before variants, so `parent_sku` may reference a product row in the same CSV.

| Column | Required | Rules and behavior |
|---|---:|---|
| `type` | Yes | Must be `variant` |
| `sku` | Yes | String, max 255; creates or updates a variant by SKU and cannot collide with any product SKU |
| `parent_sku` | Yes | Existing product SKU or product SKU in the same file; must differ from variant SKU |
| `name` | Yes | String, max 255 |
| `price` | No | Number, minimum 0 |
| `stock_qty` | No | Integer, minimum 0 |
| `attributes` | No | Valid JSON array/object |
| `weight_oz` | No | Number greater than 0, maximum 2,400 |
| `length_in` | No | Number greater than 0, maximum 200 |
| `width_in` | No | Number greater than 0, maximum 200 |
| `height_in` | No | Number greater than 0, maximum 200 |

## Example

```csv
type,sku,parent_sku,name,price,stock_qty,status,category_slug,in_stock,is_featured,attributes,weight_oz,length_in,width_in,height_in
product,QUEEN-BAG-001,,Queen Bag,129.00,20,published,bags,true,false,,24,14,10,5
variant,QUEEN-BAG-001-BLK,QUEEN-BAG-001,Queen Bag - Black,129.00,8,,,,,"{""color"":""Black""}",24,14,10,5
```

## Atomicity and response

- Any row error prevents all writes, even when `dry_run=false`.
- A valid `dry_run=false` import writes all product rows and then all variant rows inside one database transaction.
- Each result row reports `row`, `type`, `sku`, `action` (`create`, `update`, or `error`), and field-keyed `errors`.

Successful preview/import returns `200`:

```json
{
  "success": true,
  "message": "CSV preview completed.",
  "data": {
    "summary": {
      "rows": 2,
      "creates": 2,
      "updates": 0,
      "errors": 0
    },
    "rows": [],
    "committed": false
  },
  "errors": null
}
```

A row or file error returns `422`; no products or variants are changed.
